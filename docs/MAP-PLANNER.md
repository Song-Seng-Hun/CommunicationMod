# 지도 펜과 경로 계획

지도 위에 **계획을 표시하는 기능**입니다. 손그림이나 경로 편집은 방 이동,
보스 진입, 카드 사용을 실행하지 않습니다. 기존 지도 호환 수정과 별도로
게임 안의 표시·입력·MCP 조회를 연결했습니다.

## 사람이 쓰는 방법

새 테스트 실행본에서 지도를 열면 왼쪽 위에 도구막대가 나타납니다.

- **펜(깃털 아이콘)**: 누른 뒤 마우스 왼쪽 버튼을 드래그해 그립니다.
- **경로**: 노드를 차례로 클릭하면 청록색 직선과 방향 화살표로 연결합니다.
  이미 경로에 있는 노드를 다시 누르면 그 노드까지 경로를 줄입니다.
  실제 지도에 그려진 간선으로 이어진 노드만 연결합니다. 보스 아이콘도 선택할 수 있습니다.
- **지우개**: 선 근처를 클릭하면 해당 손그림 획을 지웁니다. 경로는 되돌림이나
  초기화를 사용합니다. 손그림을 경로 노드로 자동 해석하지 않습니다.
- **되돌림**: 최근 손그림 추가·획 삭제·경로 편집·초기화를 되돌립니다(최대 16회).
- **초기화**: 현재 지도의 손그림과 계획 경로를 모두 지웁니다. 되돌릴 수 있습니다.
- 선택 중인 도구를 다시 누르면 편집을 종료합니다. 편집 중에는 마우스·컨트롤러의
  방 선택을 차단하지만 휠 스크롤은 유지합니다. 이미 게임이 수락한 이동은 취소하지 않습니다.

손그림은 지도 좌표로 보관하고, 노드 경로는 실제 hitbox 갱신 시 읽은 위치에
붙입니다. 따라서 스크롤·배율과 다운폴 역방향 지도에 화면 픽셀을 고정하지 않습니다.
상단 도구막대/패널 영역은 그림 영역에서 제외됩니다.

## 에이전트가 쓰는 방법

기존 로컬 Downfall MCP를 사용합니다. 별도 원격 연결이나 서버가 필요하지 않습니다.
플러그인 갱신 후 **새 Codex 작업**에서 최신 도구 스키마를 불러오세요.

### 가볍게 확인

```json
{"view":"map_plan"}
```

위 인자로 `sts_get_state`를 호출하면 session/state ID와 다음 정보만 읽습니다.

```json
{
  "map_plan": {
    "map_id": "map-2-act-1",
    "revision": 7,
    "route_author": "human",
    "route_count": 3,
    "current_node": "2,13",
    "next_planned_node": "2,12",
    "status": "on_route",
    "stroke_count": 4,
    "editing": false
  }
}
```

이는 설명용 예시입니다. 실시간 ID·위치·변경 번호를 대신하지 않습니다.
이 모드는 카드 본문·덱·지도 전체·경로 전체·손그림 좌표·행동 목록을 반환하지
않습니다. `(map_id, revision)`이 바뀌었을 때만 계획의 상세 내용을 다시 읽으면 됩니다.
실제 이동은 계획을 수정하지 않으므로 **revision이 같아도 current_node는 달라질 수 있습니다.**

손그림만 있는 경우 `stroke_count > 0`이지만 경로는 `unplanned`일 수 있습니다.
`off_route`에서는 다음 노드를 추측하지 않습니다. 시작 전 계획 첫 노드는
`planned_start`로 별도 제공하며, `next_planned_node`와 실제 도착 위치를 혼동하지 않습니다.

### 직선 경로 표시

1. 기본 `sts_get_state`(decision view)에서 현재 행동과 ID를 확인합니다.
2. 필요할 때만 `sts_get_context(section="map")`로 `node_id`와 `children`을
   읽습니다. 기존 좌표도 유지됩니다. 보스의 계획 ID는 `boss`입니다.
3. `sts_get_context(section="map_plan")`는 전체 계획 노드 순서를 돌려줍니다.
4. 제공된 `run.map.plan` 행동을 **현재** session/state ID로 호출합니다.
   아래 `arguments` 값의 map_id/revision은 행동 스키마에 나온 값을 사용합니다.

```json
{
  "action_id": "run.map.plan",
  "arguments": {
    "map_id": "map-2-act-1",
    "revision": 7,
    "nodes": ["1,14", "2,13", "2,12"]
  }
}
```

좌표는 예시이며 실제 지도에 있는 연결을 사용해야 합니다. 이 행동은 전체 경로를
교체합니다. `nodes: []`는 경로만 지우며 손그림은 보존합니다. 실제로 이동하려면
별도의 제공된 `run.map.<x>.<y>` 또는 `run.map.boss` 행동이 필요합니다.

사람이 편집 중이거나 현재 지도/변경 번호가 달라졌으면 MCP 편집은 거부됩니다.
사람/에이전트가 마지막으로 경로를 편집했는지는 `route_author`로 구분합니다.
이는 경로 작성자이며, 실제 방 이동을 누가 실행했는지를 주장하는 필드는 아닙니다.
미래의 비행·장화·순간이동 자원은 예측하지 않고 **공개된 지도 간선만** 검증합니다.

## 저장 범위와 한도

- 첫 버전은 실행 세션 내 메모입니다. 지도를 닫았다 열어도 유지하지만 새 지도·막·런,
  또는 게임 재실행에서는 초기화합니다. 세이브 파일에 쓰지 않습니다.
- 획 128개, 전체 8,192점, 한 획 2,048점, 계획 노드 64개, 되돌림 16개로 제한합니다.
- 원시 손그림 좌표는 전체 게임 관측에도 넣지 않습니다. 선 수와 계획 정보만 전달합니다.
- 원본 Steam 실행본/세이브와 이전 격리 테스트 실행본은 유지합니다. 새 복사본에는
  이전 테스트 프로필/진행 데이터를 자동으로 이식하지 않았습니다.
