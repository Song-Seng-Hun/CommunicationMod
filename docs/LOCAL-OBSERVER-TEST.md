# 로컬 관찰 테스트 (VM 없음)

사람이 직접 플레이하고 클라이언트가 관찰 JSON을 기록하는 첫 실제 검증용입니다. 자동 카드 사용·이벤트 선택은 하지 않습니다. 전체 다운폴 호환이나 실제 플레이 통과를 의미하지 않습니다.

## 실행

작업폴더의 `Start-Downfall-Test.cmd`를 실행합니다. 이미 켜둔 Steam 게임에는 연결되지 않습니다. 이 파일이 별도의 다운폴 테스트 복사본을 실행하므로 게임은 한 개만 켜 주세요.

- Java 11은 그대로 두고 다운폴에 포함된 Java 8을 사용합니다.
- 이 테스트 프로필은 마우스·키보드용입니다. Steam 컨트롤러 기능은 사용하지 않습니다.
- Steam 시작 옵션·원본 JAR·기존 저장 파일은 변경하지 않습니다.
- 별도 작업 디렉터리와 APPDATA/LOCALAPPDATA를 사용하므로 처음 실행한 게임처럼 보일 수 있습니다. 필요하면 게임 설정에서 한국어를 선택하세요.
- 테스트 복사본의 Steam 기록 연동과 확인된 플레이 통계 전송 경로를 끕니다. VM·가상화 드라이버·OS 네트워크 차단은 사용하지 않습니다. 임의의 추가 모드까지 격리하는 보안 샌드박스는 아닙니다.

다시 빌드하고 준비하기:

```powershell
.\devtools\prepare-local-test.ps1
```

검사만 하기:

```powershell
.\devtools\start-local-test.ps1 -CheckOnly
.\devtools\start-local-test.ps1 -SmokeTest
```

`-SmokeTest`는 원래 패키지 초기화까지만 실행하고 게임 창을 열지 않습니다. 다른 Java 프로세스나 Steam 클라이언트는 종료하지 않습니다.

## 실제 플레이 체크리스트

1. 게임 언어를 확인하고 허밋으로 새 게임을 시작합니다.
2. 니오우 대사와 이벤트 본문이 표시되는 동안 기다렸다가 사람이 선택합니다.
3. 첫 전투에서 드로우 중에는 `hand_complete=false`와 빈 `hand`, 드로우가 끝나고 손패가 안정되면 완전한 손패가 나오는지 비교합니다.
4. 카드 이름·설명·키워드 및 가운데 카드 효과를 화면과 비교합니다. 손패 행에는 `hand_index`, 해당 허밋 카드에는 `dead_on_position_active`가 포함됩니다.
5. 드로우 카드 사용·턴 종료·강제 카드 선택에서도 확인합니다. 강제 선택은 일반 손패와 다른 `selection` 모드입니다.

최상위 `ready=false`, 빈 `actions`는 관찰 전용이므로 정상입니다. 손패의 준비 여부는 `observation.combat_decision` 및 `observation.game_state.combat_state.hand_complete`를 확인합니다.

## 기록

`target/local-test-ready.json`의 `runtime`이 현재 준비된 게임 폴더입니다.

- `<runtime>/recordings/<session>/observations.jsonl`: UTF-8 v2 연결/관찰 기록, 64 MiB 상한.
- 같은 폴더의 `latest-state.json`: 가장 최근 상태.
- 같은 폴더의 `client-errors.log`: 기록 클라이언트 오류.
- `<runtime>/launch-*.log`: 게임/관찰 오류. 반복 관찰 오류의 스택은 한 번만 출력합니다.

일반 관찰은 초당 최대 4번, 전투 준비 상태가 바뀌면 추가로 기록합니다. 클라이언트 종료·정체·로그 상한은 기록만 중단하며 사람의 게임 조작은 차단하지 않습니다. 게임 종료 시 해당 클라이언트도 종료합니다.

`observation_unavailable`은 관찰 실패이며 지원 완료로 간주하지 않습니다. 기존 클릭/호버 패치에 의존하는 일부 미니게임은 이번 범위 밖입니다. 알려진 대사 렌더 경로·일반 전투 손패·표준 선택 화면부터 검증합니다.

JAR·설정·저장·로그는 Git에서 무시되는 `target`에 생성합니다. 원본으로 돌아가려면 테스트 게임을 종료하고 기존 Steam 항목으로 실행하면 됩니다.

## 구현 및 검증 경계

- 원래 패키지의 메타데이터·enum·초기화 함수를 유지합니다. 예전 CommunicationMod 실행/초기화 루틴을 덧붙이지 않습니다.
- 입력 JAR 네 개의 해시를 고정하고 생성 파일과 원본 해시를 시작 직전에 확인합니다. 원본 업데이트 후에는 재준비가 필요합니다.
- 기존 대사·전투·키워드 raw 패치와 관찰에 필요한 턴/큐 변경 알림만 추가합니다. 클릭/호버 행동 패치는 설치하지 않습니다.
- `ObserverSession`은 v2 코어를 사용하지만 행동 콜백은 등록하지 않습니다. 구버전 요청을 거부하고 내부 적 행동 번호·기본 공격 수치·비공개 의도 수치를 출력에서 제외합니다.
- 정상 렌더 완료 뒤 게임 스레드에서 관찰/요청을 처리합니다. I/O 스레드는 게임 객체에 접근하지 않으며 큐는 각각 16개로 제한합니다. 초기 연결 응답을 기다리며 게임 스레드를 멈추지 않습니다.
- 기존 `DevLoader`, `DevGameLauncher`, legacy 명령 차단은 유지하지만 이 새 관찰 실행 경로는 막지 않습니다. VM은 요구하지 않습니다. 실제 v2 행동 연결은 별도 단계입니다.

검증 결과 및 미검증 항목은 `DOWNFALL-IMPLEMENTATION.md`를 참고하세요.
